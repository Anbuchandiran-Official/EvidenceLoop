# EvidenceLoop — engineering decisions

**Scope.** A local research experiment for Thuli Problem 3, using FastAPI, Pydantic, SQLite and a small static frontend. The differentiator is an inspectable challenge, correction and transfer loop. This document is intentionally short enough for two rendered pages with ordinary document settings.

1. **Explicit orchestration instead of an agent framework.** A visible plan precedes searches; async tasks parallelize independent work under fixed limits. Pydantic records connect claims, citations, audits and repairs. A framework or distributed queue would add state and abstractions without improving this experiment. SQLite is adequate for one local user; server restarts mark unfinished work interrupted rather than silently resuming it. More users would require durable jobs and stronger transactional boundaries.

2. **Independent evidence retrieval, with a programmatic provenance gate.** The auditor sees one claim and newly fetched documents, not analyst excerpts, memory or earlier verdicts. An exact-quote check rejects invented evidence. Entity, amount, unit, date, period and metric must be covered. Arithmetic is checked separately, while input meaning still requires judgment. A quote appearing on a page is not proof that it entails a claim; separate contexts using one model family remain vulnerable to correlated errors. This is why fixed external labels and human review exist.

3. **Abstention is a first-class result.** Factual verdicts are SUPPORTED, UNSUPPORTED and CONTRADICTED. Fetch/model/quote failures are a separate axis with no invented factual verdict. “Store count increased by 50” does not establish gross openings when closures are unknown: UNSUPPORTED is the correct distinction. One correction opportunity per flagged claim prevents unbounded repair loops. Original claims, initial verdicts, revisions and final verdicts remain inspectable. Unresolved claims remain flagged, and withdrawals are visible.

4. **Learn checks, not answers.** A lesson is created only from a quoted failed claim whose changed revision receives a supported, quote-verified re-audit. Each lesson retains evidence, scope, origin and later uses. Retrieval is intentionally simple scoped keyword matching; facts are fetched again. Fixture memory and live memory are partitioned. A held-out synthetic company demonstrates retrieval; both fixture arms already make the correct metric distinction, so the observed answer-quality difference is zero. Forcing the memory-off arm to err would manufacture a gain.

5. **Measure with frozen labels and paired questions.** Six injected errors, three correct controls and one unavailable citation test both catching mistakes and avoiding over-rejection. Expected labels never enter auditor inputs. The eight-question suite increases difficulty and reuses entities. Four questions train memory; four are paired with memory disabled/enabled from a frozen snapshot and equal budgets. Held-out writes are disabled and arm order alternates. Independent human labels assess correctness and completeness; auditor judgments are not ground truth. Tokens come from provider usage, and rupee costs remain unknown without configured, verified price assumptions.

**Testing and observed limits.** Pytest exercises actual orchestration, refetch isolation, exact quotations, arithmetic, missing citations, inaccessible sources, one-step repairs, transfer isolation, provider request formats and API boundaries. A real Chrome smoke test covers the UI and mobile width. The offline challenge caught 6/6 errors with 0/3 false flags and one unverifiable case. This measures the deterministic fixture implementation, not an LLM. Gemini preflight returned HTTP 503, and Tavily was unconfigured; there is no completed live evaluation or evidence of model improvement or cost savings. Actual artifacts preserve these boundaries.

**Trade-offs and next two weeks.** We fetch static HTML/text/PDF within strict limits; JS-only sites, scanned reports and large documents can fail. A reserved corroboration search is bounded and cannot establish exhaustive coverage. Keyword memory misses paraphrases, and a shared model can agree with itself incorrectly. Next: restore provider access, complete independent human labels, repeat paired runs on frozen page snapshots and live pages, use a second auditor model family, evaluate retrieval precision, and tighten egress with socket-level DNS pinning before any hosted deployment. Optimize cost only after correctness and coverage are measured.
